LogiFlow Support — Autonomous Customer Support & Triage Agent

About LogiFlow

LogiFlow is an automated inventory and supply chain orchestration platform for mid-sized e-commerce brands. It sits between your sales channels (Shopify, Amazon Seller Central) and your physical fulfillment network — regional warehouses, 3PLs, and shipping couriers (FedEx, DHL) — maintaining a single source-of-truth inventory ledger, routing every order to the right warehouse under configurable shipping rules, generating courier labels, and writing tracking back to the channel the customer bought from. Brands on LogiFlow stop overselling during flash sales, stop hand-picking couriers order-by-order, and stop reconciling channel stock levels in spreadsheets.

This repository contains LogiFlow's internal Support Console: an autonomous ticket triage system built on a LangGraph multi-agent pipeline. Every inbound ticket is classified and urgency-scored, checked for churn signals, answered from the product knowledge base via RAG (ChromaDB + local sentence-transformer embeddings + Gemini 2.5 Flash), and — when the situation calls for it — escalated to the human queue with a prepared handoff summary and tier-specific retention talking points. Human agents work out of a React console with a live inbox, real-time pipeline streaming, an operations dashboard, and a browsable knowledge base.

Highlights

  • Multi-agent orchestration with LangGraph — not a single prompt chain: a stateful graph with conditional and parallel edges (critical tickets skip RAG entirely; churn-risk tickets fan out into RAG + a parallel retention-alert branch).
  • Grounded, not generated — the RAG agent only answers from retrieved knowledge-base chunks above a confidence threshold, and explicitly escalates instead of guessing when the docs don't cover the issue.
  • Rules underneath the model — every agent pairs an LLM call with a deterministic policy layer (outage language, enterprise severity, frustration/cancellation phrase bank) that the model can never under-triage past, so the pipeline degrades safely if the LLM is unavailable or wrong.
  • Full reasoning trail, end to end — every ticket persists which category/urgency it got and why, which doc chunks were retrieved with relevance scores, and the exact escalation/retention reasoning — all visible in the UI, not just logged.
  • Real-time pipeline streaming — submitting a ticket shows each agent's step completing live over SSE, not a spinner.

Stack: FastAPI + SQLAlchemy/SQLite · LangGraph · Gemini 2.5 Flash (gemini-2.5-flash-preview-05-20) · ChromaDB + sentence-transformers (all-MiniLM-L6-v2, fully local) · React + Vite + Tailwind CSS · SSE for live pipeline streaming.

Setup

Backend

cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env        # then set GEMINI_API_KEY
uvicorn main:app --reload --port 8000

First startup takes a minute: it creates and seeds logiflow_support.db (8 customers, 30 tickets), downloads the all-MiniLM-L6-v2 embedding model (~90 MB, once), and embeds the 7 knowledge base docs into ChromaDB (backend/chroma_db/).

GEMINI_API_KEY is optional: without it (or if the API errors), every agent falls back to its deterministic rule-based path, so the full pipeline, routing, and UI still work — drafts are template-based instead of LLM-written.

Frontend

cd frontend
npm install
npm run dev                 # http://localhost:5173  (proxies /api → :8000)

How to Test

Open the Inbox → Submit Ticket tab, pick a customer, and try these five messages — each exercises a different graph path:

  1. Critical → straight to Escalation (RAG skipped):
    "URGENT — the entire platform appears to be down. All orders are failing to route since this morning and nothing has shipped. We are losing money every minute."
  2. Churn risk → RAG + parallel Churn Alert + Escalation with retention notes:
    "This is the third time this month inventory sync has silently died. Absolutely unacceptable. I have a demo with a competitor on Friday and I'm seriously considering cancelling."
  3. Technical integration → resolved by RAG:
    "Our Shopify webhook health shows orders/create as Not Registered and no new orders are coming in. We reinstalled the LogiFlow app yesterday while debugging a theme issue."
  4. Billing, low urgency → resolved by RAG:
    "We're about to exceed the Starter order limit. How do upgrades work — is it immediate, and is the price prorated?"
  5. Out-of-scope → RAG can't answer confidently → Escalation:
    "Can LogiFlow integrate with our custom Oracle NetSuite ERP deployment through your partner program, and what would the professional services engagement cost?"

Watch the real-time agent progress tracker during submission, then open the ticket to see the full pipeline trace, retrieved docs with relevance scores, and the editable draft.

How the Triage Logic Works

  1. Classifier & Triage (Agent 1) — Gemini classifies the ticket into one of 7 categories and proposes an urgency; a deterministic rule layer then enforces the triage policy on top of the model output: outage language ("down", "outage", "all orders failing", "data loss") always yields critical, enterprise customers with severe issues are promoted to critical, "sync stopped"/"courier not connecting"/multi-order impact yields at least high. Churn detection likewise combines the LLM with a regex bank of frustration/cancellation/competitor/recurrence phrases — either source can flag it. The LLM can never under-triage past the rules.
  2. Routing — critical tickets skip RAG entirely (an outage doesn't need a documentation link, it needs a human — fast). Churn-risk tickets fan out in parallel: RAG still drafts a response while the Churn Alert branch notifies retention. Everything else goes to RAG.
  3. RAG Resolution (Agent 2) — queries ChromaDB for the top 5 chunks, keeps those above a relevance floor (cosine-similarity ≥ 0.35), and drafts a response in LogiFlow's voice grounded only in retrieved documentation. It escalates instead of answering when fewer than 2 chunks clear the floor, or when Gemini itself judges the context insufficient (INSUFFICIENT_CONTEXT sentinel).
  4. Escalation (Agent 3) — produces the human handoff: a 2–3 sentence summary with a suggested first action, a priority label (P0–P3 mapped from urgency), and — for churn tickets — retention talking points tailored to the customer's tier (an enterprise save play looks nothing like a starter save play).

Everything each agent decides is written to agent_notes, persisted with the ticket, and rendered as the "Agent reasoning trace" in the drawer.

API Surface

Known Limitations

  • Single-process state — SSE event buffers live in process memory; running multiple uvicorn workers would split streams. Fine for a console served by one worker.
  • "Send" is simulated — the draft response Send button marks the reply as queued; there's no real outbound email/channel integration.
  • No auth — the console assumes a trusted internal network; there is no login, RBAC, or audit trail for human agents.
  • Chunk-level relevance is heuristic — the 0.35 cosine floor and 2-chunk minimum were tuned by eye against this KB; a different corpus needs re-tuning, and there's no re-ranker.
  • Churn trend is computed from ticket created_at only — a customer-level churn model (repeat tickets per account, NPS, usage) would be the real production signal.
  • Gemini preview model — gemini-2.5-flash-preview-05-20 is a preview snapshot and may be deprecated; swap the model name in backend/llm.py when it sunsets. All agents degrade gracefully to rule-based behavior on any LLM failure.
